## 1. 缺陷（Bug）

### D1 — 原生桌面端"开发模式"启动命令已过时【高】
- 证据：`server/tauri_window.py:86` → `cmd = ["cargo", "tauri", "dev"]`
- 事实：`desktop/` 是 **egui/eframe 纯原生** crate（`desktop/Cargo.toml` 无 tauri 依赖），项目内不存在 tauri CLI 配置；`scripts/dev.bat:48` 的正确做法是 `cargo run`（cwd=`desktop/`）。`git ls-files` 中 tauri CLI 相关文件均属遗留 `tauri-app/`，不在活动构建链。
- 影响：设置 `BOOTTRACKER_DEV_MODE=1` 后主界面启动失败；`is_tauri_available()` 仅凭源码存在即返回 True（`server/tauri_window.py:57-61`），因此**开发态无编译产物时每次启动都会尝试执行一条不存在的命令**并记 error 日志，然后才回退浏览器。
- 修复：
  - [x] `server/tauri_window.py:86` 改为 `cmd = ["cargo", "run"]`（并在其后补 `env["BOOTTRACKER_PORT"] = str(PORT)`，与生产模式一致）
  - [x] 同步更新 `start_tauri()` docstring（"cargo tauri dev，支持热重载" → "在 desktop/ 下 `cargo run`，便于改代码后重建"）
  - [ ] `scripts/dev.bat` 与 `tauri_window.py` 的开发命令保持单一来源（建议 dev.bat 之后仅设置 `BOOTTRACKER_DEV_MODE=1`，由后端统一拉起）——**仍待办**
- 验收：`BOOTTRACKER_DEV_MODE=1 .venv\Scripts\python.exe boot-tracker.py --debug` 能在无预编译产物时直接起 egui 窗口。→ **待用户下次开发会话实跑确认**（当前实例正占用单实例锁与 18792 端口，无法并行验证）。

### D2 — 会话"今天是否已有记录"混用 UTC 与本地日期【高】
- 证据：`server/data_store.py:242` `today_str = time.strftime("%Y-%m-%d")`（**本地**日期）与 `:264` `date(boot_time) = ?`（`boot_time` 存的是 **UTC** ISO，见 `:243`）；同文件 `:230-235` 已存在正确助手 `_utc_iso_to_local_date()`，但此处未被使用。
- 影响：UTC+8 时，本地 00:00–08:00 的开机其 UTC 日期为前一天，`today_str` 匹配不到 → `cnt == 0` → **同一台机器重启后新建"今天"的会话，把上一次未收盘会话强行按当前时间收盘**，出现"开机时间被改写/一天两条记录"。这与 README 承诺的"下次启动自动关闭遗留会话"语义冲突。
- 修复：
  - [x] `auto_close_and_new_session()` 改为按本地日期判定：新增 `_local_day_utc_range(local_date)` 求本地自然日 `[00:00, 次日00:00)` 的 UTC 边界，查询改为 `WHERE boot_time >= ? AND boot_time < ?`（**保留**"今天已有会话就不新建"的原语义，未改成"存在任何未收盘会话就不新建"，后者属产品语义变更）
  - [x] 顺带消除 `:252` 的时区假设：收盘循环补 `if boot.tzinfo is None: boot = boot.replace(tzinfo=timezone.utc)`（无时区老数据按 UTC 解释，不再因 aware/naive 相减抛异常被 `except: pass` 吞掉而永不收盘），`duration_ms` 加 `max(0, …)` 防时钟回拨
- 验收：新增用例——UTC 时间为前一日 16:30、本地为当日 00:30 时，`auto_close_and_new_session()` 不产生新会话；`pytest tests -q` 全绿。→ **已达成**：`tests/test_data_store.py` 新增 3 用例（见 7.1），45 passed。
- 跨时区抽样验证（`[已实测]`）：对本地日 2026-10-07 逐小时采样 24 点，新逻辑在 UTC+8 / UTC+0 / UTC-5 / UTC+14 下越界点数均为 **0/24**；旧写法 `date(boot_time) = 本地日期` 的漏判小时数为 **8 / 0 / 5 / 14**，与各时区偏移量一致，确认原缺陷的暴露面。
- 关联：D13（补测试）——其"会话归属"部分已随本次修复完成，其余（Rust/前端时间格式化测试）仍待办。

### D3 — 原生窗口不可用时的回退链路薄弱【中】
- 证据：`server/tauri_window.py:57-61`（`is_tauri_available()` 在只有源码时返回 True）、`:86`（随后尝试 `cargo tauri dev`）、`boot-tracker.py:186-198`（`start_tauri()` 返回 False 才回退浏览器）。
- 影响：源码态（未 `cargo build`）启动 → 尝试一条不存在的命令 → 约 8 s 后才打开浏览器；同时在 `logs/` 留下误导性 error。
- 修复：
  - [ ] `is_tauri_available()` 拆分为 `has_binary()` 与 `has_source()`，`start_tauri()` 仅在 `has_binary()` 或 `dev_mode=True` 时才尝试
  - [ ] 启动失败时把失败原因（二进制缺失 / cargo 不存在 / 进程立即退出）写进单条 warning，避免刷屏
  - [ ] `boot-tracker.py:189` 调用后增加"进程存活探测"（`proc.poll() is None`，约 0.5 s 后判定），避免 `start_tauri()` 成功但进程秒退时仍走托盘模式
- 验收：删除 `desktop/target` 后启动，3 s 内打开浏览器且日志只有 1 条 warning。

### D4 — 子进程管道只建不读【中】
- 证据：`server/tauri_window.py:101-108` 与 `server/widget.py:71-77` 均 `stdout=subprocess.PIPE, stderr=subprocess.PIPE`，全文件无任何 `readline()/communicate()`。
- 影响：Windows 匿名管道默认缓冲约 4–64 KB，子进程输出写满即阻塞在写调用 → 原生窗口/浮窗假死。当前 Rust 端输出极少（仅字体缺失 eprintln），属**潜伏故障**：一旦开启 `RUST_LOG`/panic 输出或加日志，立刻复现。
- 修复（二选一）：
  - [ ] 最小改动：改为 `stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL`（Rust 端已有 `logs/` 之外的自有 stderr 输出，丢弃即可）
  - [ ] 更佳：保留 `PIPE` 并各起一条 daemon 线程把行转发到 `logger.debug`，崩溃时还能拿到 stderr 尾行
- 验收：给 Rust 端临时注入 200 KB stdout 输出，原生窗口仍正常响应 / 进程不被阻塞。

### D5 — 时间本地化硬编码 UTC+8【中】
- 证据：`desktop/src/fmt.rs:18,29,74` 全部 `FixedOffset::east_opt(8 * 3600)`；`frontend` 侧另有本地化实现（`frontend/src/hooks/useBootData.ts` 与各页面的时间格式化）。
- 影响：非 UTC+8 用户看到的时间全部偏移；夏令时地区还会前后差 1 小时。当前项目面向中文用户，属"可接受但已固化"的技术债。
- 修复：
  - [ ] Rust：把时区偏移改为从后端下发（新增 `GET /api/version` 之外的轻量字段，或 `/api/ping` 返回 `utcOffsetMinutes`），`fmt.rs` 用 `FixedOffset::east_opt(offset)`；进阶用 `chrono::Local`（需 `clock` feature，已在默认）
  - [ ] 后端：`/api/ping`（`server/routes/data_routes.py:56`）增加 `utcOffsetMinutes` 与 `localDate`
  - [ ] 统一三端"今天的日期"来源为后端下发值，消除各方自行推算
- 验收：把系统时区改为 UTC-5 后，桌面端/网页端显示的同一会话时间一致且正确。

## 6. 有意跳过 / 不建议改（避免误当待办）

| 项 | 结论 | 依据 |
|---|---|---|
| `--background` 参数无 Python 分支 | **不改** | 仅写入自启注册串（`server/settings.py`），改注册串会破坏已装机的自启项 |
| `tauri_window.py` / `is_tauri_available` / `start_tauri` 等命名 | **不改名** | 模块名与函数名被 `server/__init__.py` 重导出、`boot-tracker.py` 引用；重命名收益低、回归风险高。若做，建议单独一个纯重命名 commit + 全量回归 |
| 实例锁不设 `SO_REUSEADDR` | **保持** | Windows 上设了会让两个 socket 绑同端口，多开破坏单实例语义 |
| 静态资源缓存策略（`assets/` 长缓存、其余 no-store） | **保持** | Vite 产物含内容 hash；`bg.jpg` 原地覆盖无 hash，长缓存会导致换图不生效 |
| `desktop/src/fmt.rs` 兜底直接截取前 10 字符 | **保持** | 仅在解析失败时使用，属合理降级 |
| 前端 `bridge/` 是否删除 | **待产品决策** | 删除会改动 `api/client.ts` 调用链与现有 2 个测试，收益是可读性 |
