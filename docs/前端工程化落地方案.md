# BootTracker 前端工程化落地方案

> 目标：将现有 vanilla JS 前端迁移到 **Vite + React + TypeScript + Ant Design + Zustand**，建立 QWebChannel Promise 化通信、开发/生产差异化调试、一键构建与 CI/CD 自动化。
> 适用范围：仅限 BootTracker 桌面应用（PyQt5 WebEngine）。

---

## 一、现状分析

| 维度 | 现状 | 痛点 |
|---|---|---|
| 前端 | `index.html` + `static/js/app.js`（单文件）+ `static/css/style.css` | 单文件难维护、无类型、无模块化、无 HMR |
| 通信 | `fetch` 到 `http://127.0.0.1:{port}/api/*`，无 QWebChannel | 原生能力（窗口控制、托盘、主题同步）只能绕 HTTP，语义错位、无超时重试、错误无分类 |
| 后端 | Python `http.server` + 装饰器路由 `registry` | 路由已解耦，可保留 |
| 构建 | PyInstaller onedir，`datas` 含 `index.html` + `static` | 无前端构建步骤，无法做 TS 编译/打包/压缩 |
| 测试 | 无 | 前后端均无自动化测试 |
| 调试 | 无远程调试；生产未显式关闭调试通道 | 线上风险与开发效率都受限 |

**约束**（来自项目记忆，迁移过程中不可违反）：
- 路由文件在通信重构期间不得改动。
- Qt UI 跨线程必须用 `pyqtSignal`。
- WebEngine flags：frozen 用 `--no-sandbox --disable-gpu-compositing`，开发用 `--use-gl=desktop`。
- Windows 任务栏需通过 `SetCurrentProcessExplicitAppUserModelID("boottracker.app")` 显示自定义图标。
- 不得引入 Chromium logging flags（会导致控制台弹窗）。

## 二、技术选型

| 层 | 选型 | 理由（贴合本项目） |
|---|---|---|
| 构建工具 | **Vite 5** | ESM 原生 HMR；构建产物为静态文件，便于 PyInstaller 打包 |
| 框架 | **React 18** | 生态成熟，适合中等复杂度后台与设置面板 |
| 语言 | **TypeScript 5** | 现有 app.js 已有大量隐式类型契约（session 结构、settings schema），TS 可固化 |
| UI 库 | **Ant Design 5** | 表格/表单/抽屉/通知齐全，契合记录管理、设置面板、备份还原等场景；ConfigProvider token 可与现有 CSS 变量主题桥接 |
| 状态管理 | **Zustand** | 轻量，无 Provider 包裹；主题、设置、会话数据天然适合独立 store |
| 路由 | **React Router 6**（Hash 模式） | WebEngine 加载本地或 http 均对 hash 友好，避免 history 模式的服务端回退问题 |
| 图表 | **ECharts**（按需） | 替代现有手写 SVG 图表，支持柱/折线/饼/热度图 |
| 测试 | **Vitest** + **Testing Library** | 与 Vite 同构，零额外配置 |
| 后端测试 | **pytest-qt** | 验证 QWebChannel、窗口控制、主题切换的 Qt 行为 |
| 代码规范 | ESLint + Prettier + Stylelint | 统一风格 |

## 四、迁移策略（分阶段）

### 阶段 0：工程骨架与并行运行
- 新建 `frontend/`，初始化 Vite + React + TS。
- `vite.config.ts` 中配置 `server.proxy`，将 `/api` 代理到 `http://127.0.0.1:18792`，实现前端独立 dev server 同时复用现有 Python API。
- WebEngine 仍加载旧 `http://127.0.0.1:{port}/`（指向 static/）；新前端在 `localhost:5173` 独立开发。
- **不改动任何路由文件**。

### 阶段 1：主题系统迁移
- 将 `style.css` 的 `:root` CSS 变量抽取到 `frontend/src/styles/tokens.css`（按项目规范分 `--bg-* / --text-* / --accent-* / --scrollbar-*`）。
- Ant Design 通过 `ConfigProvider` 的 `theme.token` 映射这些变量，保证主题切换（purple/blue/green/orange/gray/mica/material-you）与暗色/浅色在 React 组件与原生 HTML 间一致。
- `themeStore` 持有当前 `appMode` 与 `theme`，切换时同步：CSS 变量（document.documentElement.dataset）+ Ant Design token + 通过 `callNative('setTheme', mode)` 同步 WebEngine 背景色与 DWM 标题栏。

### 阶段 2：页面逐个迁移
按依赖与复杂度顺序：
1. Dashboard（今日开机卡片，纯展示，最易验证主题与数据流）
2. Records（表格 + 筛选 + 导出 CSV/JSON/XLSX，验证 Ant Design Table + 文件导出）
3. Chart（ECharts 替换手写 SVG，验证第三方库集成）
4. Settings（外观/通用/网络/关于，验证表单与 toggle）
5. Admin（记录管理/回收站/添加/备份，验证抽屉与复杂交互）

每迁移一页，在 React Router 中注册，旧页面保留至全部迁移完成。

### 阶段 3：QWebChannel 原生桥引入
见下节。将原本绕 HTTP 的原生能力（窗口控制、托盘菜单、文件对话框、版本发布、服务器重启）迁移到 QWebChannel。

### 阶段 4：切换 WebEngine 加载源
- `frontend` 执行 `npm run build`，产物输出到 `dist-static/`。
- Python `http_handler.py` 的静态文件服务根目录改为 `dist-static/`（或新增 `/app/*` 前缀路由）。
- WebEngine 加载 `http://127.0.0.1:{port}/` 指向构建后的 `index.html`。
- 验证 HMR 关闭、source map 关闭、资源路径正确。

### 阶段 5：打包集成
- 修改 `boot-tracker.spec` 的 `datas`：`('dist-static', 'dist-static')` 替换 `('static', 'static')` 与 `('index.html', '.')`。
- `scripts/build.bat`：`cd frontend && npm ci && npm run build && cd .. && pyinstaller boot-tracker.spec`。
- 验证 frozen 产物功能与开发版一致。

## 五、通信封装（核心）

### 5.1 双通道设计

| 通道 | 用途 | 语义 |
|---|---|---|
| **HTTP API** | 数据 CRUD（记录、统计、备份列表、隧道状态） | 请求-响应，可缓存，可被局域网/隧道复用 |
| **QWebChannel** | 原生能力（窗口控制、托盘、主题同步、文件对话框、版本发布触发、服务器重启） | 进程内 IPC，不走网络，安全、低延迟 |

**为何引入 QWebChannel**：当前 `recordShutdown`、`setMode`、`bumpVersion`、`restartServer` 等通过 HTTP 触发 Python 副作用，存在语义错位（副作用不应是 REST 资源）、无超时重试、错误无分类。QWebChannel 提供进程内 IPC，天然适合命令式原生调用。

### 5.2 Python 端：注册 QWebChannel 对象

在 `server/qt_window.py` 的 `open_main_window` 中，于 `QWebEngineView` 创建后注册桥对象：

```python
# server/qt_window.py（新增片段）
from PyQt5.QtCore import QObject, pyqtSlot, QVariant
from PyQt5.QtWebChannel import QWebChannel

class _NativeBridge(QObject):
    """暴露给前端的原生能力。所有方法须在 Qt 主线程执行。"""

    def __init__(self, window, controller):
        super().__init__()
        self._window = window
        self._controller = controller

    @pyqtSlot(str, str, result=str)
    def invoke(self, method: str, args_json: str) -> str:
        """统一入口：前端 callNative(method, args) → JSON 结果。
        返回 {"ok": true, "data": ...} 或 {"ok": false, "code": "...", "message": "..."}
        """
        import json
        try:
            args = json.loads(args_json) if args_json else {}
        except Exception as e:
            return json.dumps({"ok": False, "code": "BRIDGE_BAD_ARGS", "message": str(e)})

        try:
            if method == "setTheme":
                self._controller.request_theme(args.get("mode", "dark"))
                return json.dumps({"ok": True, "data": None})
            if method == "raiseWindow":
                self._controller.request_raise()
                return json.dumps({"ok": True, "data": None})
            if method == "quitApp":
                self._controller.request_quit()
                return json.dumps({"ok": True, "data": None})
            if method == "pickFile":
                # 调用 QFileDialog，返回选中路径
                from PyQt5.QtWidgets import QFileDialog
                path, _ = QFileDialog.getOpenFileName(
                    self._window, "选择文件", "", args.get("filter", "All Files (*)")
                )
                return json.dumps({"ok": True, "data": path})
            # 其它原生能力...
            return json.dumps({"ok": False, "code": "BRIDGE_UNKNOWN_METHOD",
                               "message": f"unknown method: {method}"})
        except Exception as e:
            return json.dumps({"ok": False, "code": "BRIDGE_INTERNAL", "message": str(e)})

# 在 open_main_window 中：
channel = QWebChannel()
channel.registerObject("nativeBridge", _NativeBridge(w, _controller))
view.page().setWebChannel(channel)
```

前端注入 `qwebchannel.js`（Qt 自带，PyInstaller 需打包 `PyQt5/QtWebEngine/resources/qtwebchannel.js` 或从 CDN 兜底）。

### 5.3 前端：Promise 化封装

```typescript
// frontend/src/bridge/qwebchannel.ts
import { BridgeError, BusinessError } from './errors';

type BridgeResult<T> = { ok: true; data: T } | { ok: false; code: string; message: string };

let qtBridge: any | null = null;
let initPromise: Promise<void> | null = null;

/** 初始化 QWebChannel（仅在 WebEngine 环境） */
export function initBridge(): Promise<void> {
  if (initPromise) return initPromise;
  initPromise = new Promise((resolve, reject) => {
    // @ts-ignore - qt 全局由 qwebchannel.js 注入
    if (typeof qt === 'undefined' || !qt.webChannelTransport) {
      reject(new BridgeError('BRIDGE_UNAVAILABLE', 'QWebChannel not available'));
      return;
    }
    // @ts-ignore
    import('qwebchannel').then(({ QWebChannel }) => {
      // @ts-ignore
      new QWebChannel(qt.webChannelTransport, (channel) => {
        qtBridge = channel.objects.nativeBridge;
        if (!qtBridge) reject(new BridgeError('BRIDGE_NO_OBJECT', 'nativeBridge not registered'));
        else resolve();
      });
    });
  });
  return initPromise;
}

/** Promise 化 + 超时 + 错误分类的统一调用 */
export async function callNative<T>(
  method: string,
  args: Record<string, unknown> = {},
  timeoutMs = 5000,
): Promise<T> {
  if (!qtBridge) {
    throw new BridgeError('BRIDGE_NOT_READY', 'bridge not initialized');
  }
  const argsJson = JSON.stringify(args);

  const result = await new Promise<string>((resolve, reject) => {
    const timer = setTimeout(() => {
      reject(new BridgeError('BRIDGE_TIMEOUT', `${method} timed out after ${timeoutMs}ms`));
    }, timeoutMs);
    try {
      // QWebChannel 的 invokeMethod 是回调式，转 Promise
      qtBridge.invoke(method, argsJson, (raw: string) => {
        clearTimeout(timer);
        resolve(raw);
      });
    } catch (e) {
      clearTimeout(timer);
      reject(new BridgeError('BRIDGE_INVOKE_FAILED', String(e)));
    }
  });

  let parsed: BridgeResult<T>;
  try {
    parsed = JSON.parse(result);
  } catch (e) {
    throw new BridgeError('BRIDGE_BAD_RESPONSE', `invalid JSON: ${result}`);
  }

  if (!parsed.ok) {
    // 业务错误：通信成功，但业务逻辑失败
    throw new BusinessError(parsed.code, parsed.message);
  }
  return parsed.data;
}
```

### 5.4 错误分类

```typescript
// frontend/src/bridge/errors.ts
export class BridgeError extends Error {
  constructor(public code: string, message: string) {
    super(message);
    this.name = 'BridgeError';
  }
}

export class BusinessError extends Error {
  constructor(public code: string, message: string) {
    super(message);
    this.name = 'BusinessError';
  }
}
```

- **BridgeError（通信错误）**：`BRIDGE_UNAVAILABLE / BRIDGE_NOT_READY / BRIDGE_TIMEOUT / BRIDGE_INVOKE_FAILED / BRIDGE_BAD_RESPONSE`。处理策略：降级（回退 HTTP）或提示"原生功能不可用"。
- **BusinessError（业务错误）**：`BRIDGE_UNKNOWN_METHOD / BRIDGE_BAD_ARGS` 或业务自定义 code。处理策略：按 code 展示对应提示（如 Ant Design `message.error`）。

### 5.5 超时与重试

- `callNative` 内置单次超时（默认 5s）。
- 重试仅对**幂等读操作**（如 `getNativeState`）开放，写/副作用操作（`setTheme`、`quitApp`）不重试，避免重复执行。
- 封装 `callNativeWithRetry(method, args, { retries: 2, backoff: 'exp' })`，仅 `BridgeError` 触发重试，`BusinessError` 立即抛出。

### 5.6 浏览器 Mock（独立开发）

```typescript
// frontend/src/bridge/mock.ts
import type { BridgeResult } from './qwebchannel';

const handlers: Record<string, (args: any) => BridgeResult<any>> = {
  setTheme: (args) => ({ ok: true, data: null }),
  raiseWindow: () => ({ ok: true, data: null }),
  pickFile: () => ({ ok: true, data: 'C:/mock/file.txt' }),
  // ...
};

export async function callNativeMock<T>(method: string, args = {}, timeoutMs = 200): Promise<T> {
  await new Promise((r) => setTimeout(r, timeoutMs)); // 模拟延迟
  const h = handlers[method];
  if (!h) return Promise.reject(new (class extends Error {})());
  const res = h(args);
  if (!res.ok) throw new (class extends Error {})();
  return res.data as T;
}
```

在 `main.tsx` 启动时检测环境：

```typescript
// frontend/src/main.tsx
import { initBridge, callNative } from './bridge/qwebchannel';
import { callNativeMock } from './bridge/mock';

const isWebEngine = typeof (window as any).qt !== 'undefined';

export const native = isWebEngine ? callNative : callNativeMock;
// WebEngine 下尝试初始化，失败则降级 mock
if (isWebEngine) {
  initBridge().catch((e) => console.warn('[bridge] init failed, fallback to mock', e));
}
```

这样前端可在纯浏览器（`localhost:5173`）独立开发，所有原生调用走 mock，无需启动 Python。

### 5.7 HTTP API 封装（与桥并行）

```typescript
// frontend/src/api/client.ts
export class HttpError extends Error {
  constructor(public status: number, message: string) { super(message); }
}

export async function api<T>(path: string, init?: RequestInit, timeoutMs = 8000): Promise<T> {
  const ctrl = new AbortController();
  const timer = setTimeout(() => ctrl.abort(), timeoutMs);
  try {
    const res = await fetch(`/api${path}`, { ...init, signal: ctrl.signal });
    const data = await res.json().catch(() => ({ error: 'invalid json' }));
    if (!res.ok || data.error) {
      throw new HttpError(res.status, data.error || res.statusText);
    }
    return data as T;
  } finally {
    clearTimeout(timer);
  }
}
```

`vite.config.ts` 代理 `/api` → `http://127.0.0.1:18792`，生产构建后由 Python 同源服务。

## 六、调试与安全

### 6.1 开发环境
- Vite dev server（`localhost:5173`）提供 HMR。
- Python 后端正常运行在 18792。
- 需要调试 WebEngine 内 React 时，启动一个**带远程调试端口**的 WebEngine 实例：
  ```python
  # 开发模式专用（不得进入 frozen）
  os.environ["QTWEBENGINE_CHROMIUM_FLAGS"] = "--remote-debugging-port=9222 --use-gl=desktop"
  ```
  随后用 Chrome 打开 `http://localhost:9222` 调试 WebEngine 内的页面。
- **注意**：不得加 `--enable-logging` 等日志 flag（控制台弹窗）。

### 6.2 生产环境
- frozen 包中**移除** `--remote-debugging-port`，仅保留 `--no-sandbox --disable-gpu-compositing`（与现有约束一致）。
- 关闭 DevTools：在 `QWebEngineView` 上不调用 `view.page().action(...).setVisible(True)`；或拦截 `F12` / `Ctrl+Shift+I`。

### 6.3 QWebEngineProfile 安全配置

```python
# server/qt_window.py（open_main_window 内）
from PyQt5.QtWebEngineCore import QWebEngineProfile

profile = view.page().profile()
# 生产不持久化 cookie/缓存到磁盘（桌面应用通常不需要）

profile.setPersistentStoragePath("")          # 关闭持久化存储
profile.clearAllCache()                       # 启动清缓存（可选）

profile.setSpellCheckEnabled(False)
# 禁用下载管理器（按需，桌面应用通常不需要）
# profile.downloadRequested 连接到拒绝槽
```

### 6.4 本地内容访问策略
现有代码设置了 `LocalContentCanAccessFileUrls` / `LocalContentCanAccessRemoteUrls`。迁移后页面由 Python HTTP 服务（http://），不再需要 file:// 访问远端，**可收紧为默认**，减少攻击面。

## 八、风险点与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| Ant Design 体积偏大（gzip ~300KB） | 首屏加载慢 | 按需引入 + Vite 自动 tree-shaking；WebEngine 本地加载无网络延迟，可接受 |
| QWebChannel 与 React 事件循环差异 | 异步回调时机异常 | 统一走 `callNative` Promise 封装，禁用裸 invoke |
| WebEngine 对 SPA 路由兼容 | 刷新 404 | 使用 Hash 路由，避免 history 模式 |
| PyInstaller 未打包 qwebchannel.js | 桥初始化失败 | 在 spec `datas` 显式加入 `qwebchannel.js`，或从 `PyQt5.QtWebEngine` 资源路径加载 |
| 迁移期间双份前端维护成本 | 回归风险 | 分阶段严格隔离，旧 `static/` 保留至全部页面迁移并验证后删除 |
| frozen 模式下 GPU 合成失败 | 白屏 | 沿用现有 `--disable-gpu-compositing` 约束，不引入新 flag |
| 主题 token 与 CSS 变量不同步 | 主题切换闪烁 | `themeStore` 作为单一事实源，CSS 变量与 AntD token 同源派生 |

### 回滚策略
- 保留 `static/` 旧前端与 `index.html`，直到阶段 5 验证通过。
- `boot-tracker.spec` 保留可切换的 `datas` 配置注释，构建失败可快速切回旧产物。
- QWebChannel 引入失败时，`callNative` 自动降级到现有 HTTP API（保留 `/api/raise-window`、`/api/set-theme` 等作为兜底）。
